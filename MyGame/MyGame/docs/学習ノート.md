【 3Dアニメーション & 3D数学 実践学習ノート 】

1. ボーン追従と武器・コライダーのリアルタイム同期

■ 概要
アニメーションするキャラクターの手首ボーンに剣のモデルをアタッチし、さらに剣の刃に沿って設定した「複数スフィアコライダー（だんご3兄弟）」を、剣の傾きに合わせて正確に追従させる仕組み。

■ 処理の4ステップ
(1) 手首のワールド行列の算出
    handMatrix = worldMatrices[handBoneIndex] * playerWorld
    - プレイヤー自身の位置 (playerWorld) とボーンのローカル変形を掛け合わせ、手首の「最終的なワールド座標と回転」を求める。

(2) 行列の分解 (XMMatrixDecompose)
    - 合体状態の handMatrix から「拡大率 (scale)」「回転 (rot)」「位置 (trans)」を取り出す。
    - 取り出した位置 trans をそのまま剣モデルの位置 (transform.SetPosition) に割り当てる。

(3) 最終回転角度の合成
    combinedRot = localRot * handRotMat
    - 武器モデル固有の補正角度 (localRot) と手首の回転 (handRotMat) を掛け合わせる。

(4) コライダー（オフセット）の回転適用 (XMVector3Transform)
    - 初期化時に記録した基準のオフセット位置 (baseOffset) に回転行列 combinedRot を適用。
    - 剣の刃の傾きに合わせて、コライダーの位置を斜め方向に回転・移動させる。


2. 3Dアニメーション計算の仕組み (UpdateAnimation)

(1) 前処理・バッファ確保
・outLocalMatrices.resize(m_bones.size(), XMMatrixIdentity())
  モデルのボーン数に合わせて配列を割り当て、初期値として「単位行列（変形なしの基本姿勢）」を敷き詰める。
  アニメーションデータがないボーンが存在しても、モデルが崩壊・クラッシュしないようにするための安全対策。

(2) 再生時間（Ticks）の循環計算
・Ticks単位への変換: timeInTicks = timeInSeconds * ticksPerSecond
・ループ計算 (fmod): fmod(timeInTicks, duration) を使い、時間がアニメーションの長さを超えても 0 〜 duration の範囲に余りとして収め、自動ループさせる。
・単発再生 (std::min): アニメーション長さを超えないようにクランプし、末尾のフレームでピタッと停止させる。

(3) ボーン名とアニメーション名の表記揺れ吸収（クレンジング）
AssimpやMixamoなどの外部ツールを経由した際に発生する「ボーン名の不一致」をコード側で自動補正する。
・mixamorig: 接頭辞の削除: substr(pos + 10) でプレフィックスをカット。
・Assimpダミーノード (_$AssimpFbx$_) の削除: find("_$") 以降のゴミ文字を切り捨て、純粋なボーン名で照合を行う。

(4) キーフレーム補間（Lerp と Slerp）

(補足) キーフレーム間の進捗率（factor）算出アルゴリズム

アニメーションを滑らかに再生するためには、「今の時間が、前のコマと次のコマの間の『何%』の位置にあるか」を毎フレーム計算する必要がある。

① 該当キーフレームの検索
FindKeyIndex を用いて、現在の animationTime が収まるキーフレームのインデックス (idx) と、次のインデックス (nextIdx) を取得する。

② 区間時間 (dt) の算出
dt = Keys[nextIdx].time - Keys[idx].time
- 前のコマから次のコマへ移行するのにかかる総時間を求める。

③ 進行率 (factor) の算出
factor = (animationTime - Keys[idx].time) / dt
- 「今の時間」から「前のコマの時間」を引いたものを dt で割ることで、現在の進行率（0.0 〜 1.0）を算出する。
- ゼロ除算 (dt == 0.0f) を防ぐための三項演算子でのガードや、浮動小数点の計算誤差による 0.0 未満・1.0 超えを防ぐための std::clamp による安全対策を施している。

この factor を Lerp / Slerp 関数に渡すことで、フレームレートに依存しない滑らかなアニメーシ

・スケール (Scale) : 線形補間 (Lerp) / 使用関数: XMVectorLerp
  前後のコマの間を直線的に拡大縮小

・回転 (Rotation) : 球面線形補間 (Slerp) / 使用関数: XMQuaternionSlerp
  クォータニオンの長さを保持し、等角速度で回転

・位置 (Position) : 線形補間 (Lerp) / 使用関数: XMVectorLerp
  前後のコマの間を直線移動

※ なぜ回転は Slerp で補間するのか？
Lerp で回転を補間すると、中間地点でクォータニオンの長さ（ノルム）が 1.0 より小さくなり、モデルが縮んで歪む原因になる。さらに回転スピードが不均一になる。
Slerp は常に半径 1.0 の球面上を沿って移動するため、長さ 1.0 を保ち、均一なスピード（等角速度）で滑らかに回転させることができる。

(5) ローカル行列の合成（SRTの法則）
補間された各要素から変換行列を作成し、必ず以下の順番で掛け合わせる。

M_local = scaleMat * rotMat * transMat

※ なぜ Scale -> Rotate -> Translate なのか？
移動 (T) を先にしてしまうと、原点から離れた位置で回転 (R) が適用されるため、自転ではなく「原点を中心とした公転（巨大な円を描いて回る）」になってしまうから。


3. DirectXMath 重要型・関数チートシート

■ 2大基本型
・XMVECTOR: 4つの数値（X, Y, Z, W）を一度に処理できる高速計算用の型。位置・向き・クォータニオン等に使用。
・XMMATRIX: 4x4 の行列型。拡大・回転・移動の変換を1つにまとめて保持する。

■ 主要関数一覧
・XMMatrixDecompose: 4x4行列から Scale / Rotation / Translation の成分を分離抽出する。
・XMVector3Transform: 位置・方向ベクトルに行列（回転など）を掛け合わせて、変形後の座標を求める。
・XMVectorLerp: 2つのベクトルの間を進行割合 factor（0.0 〜 1.0）に応じて直線補間する。
・XMQuaternionSlerp: 2つの回転クォータニオン間を球面上で滑らかに補間する。
・fmod(a, b): 浮動小数点数 a を b で割った余りを計算し、時間をループさせる。


4. トラブルシューティング & 設計の工夫

・単一AABBから複数スフィアへの変更:
回転に対応できないAABBや、剣全体をカバーできない単一スフィアから、刃の芯に配置した複数スフィア（だんご3兄弟）へ変更。手首ボーンのワールド回転を行列合成で適用することで、剣のあらゆる軌道に対して正確な攻撃判定を実現した。

・データ駆動化 (WeaponData 構造体):
武器の回転補正角やオフセット値をコード内に直接ベタ書き（ハードコード）せず、構造体として分離。これにより Weapon クラス自体を改修することなく、新しい武器（槍や斧など）を追加・調整できる汎用性を担保した。
